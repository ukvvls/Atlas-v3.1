# ATLAS V3.1 — Fresh Repository

واجهة مذاكرة مستقلة تعمل على GitHub Pages.

## النشر
1. أنشئ مستودع GitHub جديدًا.
2. ارفع `index.html` و`.nojekyll` و`README.md` إلى جذر المستودع.
3. Settings → Pages → Deploy from a branch → `main` → `/(root)`.

## PDF حتى 500 MB
- يضع الموقع حد اختيار/رفع قدره 500 MiB (500 × 1024 × 1024 bytes).
- يرفع الملف إلى Gemini Files API على دفعات متتابعة بحجم 8 MiB لتقليل ضغط الذاكرة مقارنة بإرسال الملف كله كطلب واحد.
- ينتظر حتى تصبح حالة الملف ACTIVE قبل بدء التحليل، ويعرض تقدم الرفع وأخطاء API برسائل أوضح.
- هذا لا يعني ضمان تحليل كل PDF بهذا الحجم: Google قد يفرض حدودًا مستقلة على حجم الملف، وعدد الصفحات، وتعقيد المستند، والحصة، وتوافر النموذج. بعض الملفات قد تحتاج تقسيمًا حتى لو كانت أصغر من 500 MB.
- الملفات الممسوحة ضوئيًا تُرسل كـ PDF إلى Gemini ليعالج الصفحات المرئية، لكن دقة OCR ليست مضمونة لكل خط/صورة.
- القيمة الافتراضية للنموذج `gemini-3.8-flash` ويمكن تغييرها من إعدادات Gemini. يجب التأكد من أن الاسم متاح لمفتاح API في Google AI Studio؛ لا يوجد اسم نموذج واحد مضمون لكل الحسابات والمناطق.

## معالجة مشاكل AI
- زر اختبار الاتصال يفحص المفتاح واسم النموذج قبل التحليل.
- يتم التفريق بين أخطاء المفتاح/الصلاحيات، النموذج غير المتاح، الحصة، رفض الملف، وأخطاء الخادم.
- يرفع الموقع الملف ثم ينتظر اكتمال معالجته قبل إرساله إلى النموذج.
- لا يمكن تشغيل Gemini بدون API key صالح وحصة API متاحة.

## الأمان والخصوصية
- مفتاح API محفوظ في LocalStorage ويُستخدم مباشرة من المتصفح. كلمة مرور قفل الإعدادات مجرد قفل واجهة وليست حماية للمفتاح.
- لا تنشر الموقع بمفتاح شخصي مضمّن. للاستخدام العام تحتاج Backend/Cloudflare Worker يخفي المفتاح ويضع حدودًا للاستخدام.
- ملفات PDF تُرسل إلى Google Gemini لمعالجتها.
- بيانات الدراسة محفوظة محليًا على هذا الجهاز والمتصفح؛ لا توجد مزامنة سحابية في هذه النسخة.
- راجع مخرجات الذكاء الاصطناعي مع الكتاب الأصلي.
